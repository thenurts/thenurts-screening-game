# Zoey's Big Calls (`big-calls`) · v1 (build pack JD1 v1.1) · built 2026-09-29

**Trait:** `judgement` (MIB 0–100) · passive: `resilience` (the first unlucky smart call), `learning` (practice pickup + first-use probe = the first ⏳ call) · **Host:** Zoey, class event captain.
**Source:** Game Ideas build pack JD1 v1.1 (`11-game-concepts.md`) + `judgement-reference.py` (copied to `tests/judgement-reference.py`) + `judgement-content.json`.

## How it plays
10 calls (Form A = the first real attempt of run 1; restarts and later runs = Form B; developer mode can force either). Each **call card** shows a situation icon + ≤ 10 words, **two options**, a **worth badge** (10 / 20 / 30, which drops as checks cost points), sometimes **⏳ Urgent**, an optional face-up first clue, one "? clue" chip per clue still hidden, and a **live tally** (arrows per side; the leading side is highlighted).
- **Check · strong clue · −2** (or weak; −6 when urgent) reveals the next clue: a label + 1 arrow (weak) or 2 (strong) pointing at the option it favours. It hides after 3 checks.
- **Tap an option** at any time. The result panel shows the outcome, the points (worth − check costs if it went your way, else 0) and **Smart call ✓** when the choice followed the tally (**≈ Close call** on a tie). Zoey: "Unlucky! But that was the smart call." **Next call ▶** moves on.
- No timer. The real round gives no feedback about checks.

**Practice (2 calls, learn by doing):** P1 (worth 30, a tie, strong clue next: check once, then follow the tally) and P2 (worth 10, urgent, weak clue next: just decide). A wasted check, a missed check or going against the tally → Zoey explains and the call restarts; after 2 tries the fail-safe says the right move and pulses its button. Logged `jd_tutorial {step, tries, usedFailSafe}`.

## Scoring (build pack §5; ScoringConfig `jd.*` later)
judgementScore = 100 × (0.5 decisionAccuracy + 0.5 infoValue). decisionAccuracy = worth-weighted share of calls that followed the tally at decision time (a tie counts as right); infoValue = good ÷ (good + wasted + missed) checks (a check within ±0.5 points of break-even is neutral). Reference bots (identical in JS): wise 100 · best rule of thumb 72.2 · never check 50.0 (both forms).
Flags: `impulsive` (≥ 3 missed, 0 checks) · `overChecker` (≥ 4 wasted) · `againstEvidence` (decisionAccuracy < 0.6) · `tutorialStruggle` (a practice fail-safe) · `repeatAttempt`.

## Data recorded
- **Rounds `metrics_json`:** the above + `smartCalls` (primary, shown), `points`, `checksMade`, `form`, `callLog` ("id checks side tally ok|no [missed] won|lost points" per call, for re-scoring), `unluckyNext` (followed / strayed / none), `learn {firstUse, pickup}`, `idleNudges`, `idleMs`.
- **Summary columns:** judgementScore, decisionAccuracy, infoValue, good, wasted, missed, smartCalls, form, flags.
- **RoundTraces:** `jd_check {form, call, n, strength, voi, verdict, cost}`, `jd_call {form, call, choice, tallyAtDecision, correctExAnte, checks, missedCheck, worth, urgent, outcome, points, ms}`, `jd_unlucky_next {call, followedTally}`, `jd_tutorial`, `help_open`, `idle`.

## Deviations (for Adrian / Game Ideas thread)
1. Events go to the round trace, not Interactions rows (event policy v1.8).
2. Outcome text is generic ("It was Hall!") because the content has no per-call outcome lines; flavour only.
3. Situation icons are mapped in `GameScene.js` (`ICON`), so `content.json` stays identical to the Game Ideas file.
4. The worth badge never shows below 0 (an urgent 10-point call with 2+ checks); scoring ignores points anyway.

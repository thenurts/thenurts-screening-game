# Mia's Fix-It Kit (`fix-it-kit`) · v1 (build pack CR1 v1) · built 2026-09-28

**Trait:** `creative` (MIB 0–100) · passive: `resilience` (the blocked moment), `learning` (practice pickup) · **Host:** Mia, the sports-day organiser.
**Source:** Game Ideas build pack CR1 v1 + `fixit-reference.py` (copied to `tests/fixit-reference.py`) + `fixit-content.json`.

## How it plays
3 problems per form (A = the first real attempt of run 1; restarts and later runs = B; developer mode can force either). Each problem card shows a picture, the title, the job, **Ideas found** and **6 tries dots**. Tap or drag 1–2 of the 8 kit objects into the **Fix tray**; for each one a picker asks **"Use its…"** (the everyday use + its properties; nothing pre-selected). **Try it** checks the try against the curated fixes:
- a **new idea** (a new mechanism) → green dot, Mia's line, "✓ New idea!";
- the **same idea** again (another object doing the same thing) → grey dot, "Same idea: try a different way";
- **doesn't work** → peach dot, "Hmm, that won't fix it." (no hint).
The **blocked moment** (after the first new idea on problem 2): the umbrella (A) / hair clips (B) are taken away and grey out. **Done** moves on at any time. No timer anywhere. The end card lists only the fixes the player found (Adrian's open question 2, recommended default).

**Practice (learn by doing):** the hot bench with a 4-object kit; find 2 different fixes. After 4 tries without that, one working fix is put in the tray and Try it pulses (fail-safe). Logged `cr_tutorial {tries, usedFailSafe}`; feeds learning `pickup`.

## Scoring (build pack §5; ScoringConfig `cr.*` later)
creativeScore = 100 × (0.30 fluency + 0.25 originality + 0.20 flexibility + 0.15 hitRate + 0.10 blockedRecovery), with the weights re-normalised if blockedRecovery is n/a. Explorer bot 83.6 (A) / 80.0 (B); everyday-uses-only 50.8 / 45.0; one idea repeated 27.6 / 23.5; random ≈ 12–13 (all identical to the reference).
Logged only: `unusualUseShare`, `doneEarly`, `invalidTries`, `triesUsed`, `tryLog` (every try: objects, chips, new / same / no).

## Data recorded
- **Summary columns:** creativeScore, fluency, originality, flexibility, hitRate, blockedRecovery, ideasFound, form, flags.
- **RoundTraces:** `cr_try {form, problem, n, objects, works, newIdea, mechanism, tier, afterBlock, ms}`, `cr_problem_end {problem, ideas, triesUsed, endedBy}`, `cr_block_next {triesToNextNewIdea, endedEarly}`, `cr_add / cr_chip / cr_remove`, `cr_tutorial`, `help_open`, `idle`.

## Deviations (for Adrian / Game Ideas thread)
1. Events go to the round trace, not Interactions rows (event policy v1.8).
2. Objects can be **tapped** as well as dragged into the tray (easier on small phones; both are logged as `cr_add {how}`).
3. The primary number shown to the player is **different ideas found**; creativeScore is staff-facing.
4. Open question 1 (the rejected-ideas list) is still yours to review: `rejectedForReview` in `content.json`.
